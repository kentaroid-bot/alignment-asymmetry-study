# Aperture Home の関数境界の検査

対象：MonkuAi contributors, Aperture Mesh Protocol, commit `d2852300dd69b1b08c89b0b537970e112496e697`。`vendor/`の3ファイルは当該commitの原本と同一。Apache-2.0のライセンスを同梱。検査用の接続部分は本研究で作成した。

実行：Node 24で `node experiments/aperture-boundaries/check.mjs`。Node標準のTypeScript構文除去を使い、モジュール読み込みだけを置換して原関数を呼ぶ。期待した性質と実際の戻り値を全てresults.jsonに保存する。

ソースを読んだ後に選んだ探索的な18項目で、14項目で期待する性質を確認、4項目で不足を確認した。「78%安全」という統計ではない。不足は3種類：

1. 対象ノード集合の外の承認も多数決へ算入する。
2. 保護対象と確認者が同一のIDでも、自己解除確認関数は真を返す。
3. 不正な日付文字列を権限の発行検査が受け入れ、期限判定がactiveを返す（2項目）。

いずれも関数を直接呼んだ入力境界の結果であり、公開アプリの画面から悪用できることを示した試験ではない。画面側は影響対象者への投票ボタンの限定や、日付の自動生成を行っている。また自己解除確認関数は、確認したsrc範囲では画面から呼ばれていない。外部入力や将来の接続を含む安全境界として使う前に、関数自体で資格・別主体・有限な時刻値を確認することを提案する。

上流の概念シミュレータ既存テスト（保護退出、誤報棄却、捕捉状態への遷移）は別途実行して成功した。これはシナリオに組み込まれた状態遷移の確認であり、独立オラクルの現実での正確さや制度の実効性を検証したものではない。アプリ全体のビルド・全テスト・実環境での安全評価は今回の範囲に含まない。元リポジトリは変更していない。
