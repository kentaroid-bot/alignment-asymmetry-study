# 方法構築A/Bの観測

Aは方法自由、BはAdaptive 0.3.2全文の適用を指示。両方に同じ動機とWORLDを渡し、方法案と自己点検を各一回答、計4回答得た。原文はoutputs/planning-A-1.jsonからplanning-B-2.json、入力は同名のinputsを参照する。要求はgpt-6-astra/high、実際の提供側識別子は未確認。これは主体の文書使用4条件とは別の比較である。

| 観点 | A：方法自由 | B：U適用 |
| --- | --- | --- |
| 比較の設計 | 差異保持・推論支援・併用を分ける成分比較を提案 | H/Qへの全文適用の有無を交差。通常動機も加える |
| 仮未来 | H/Zが初区間から各6を試作へ投入し、Wの生産準備へ進む分岐 | H/Zが区間ごとに各3を投入し、Wの生産準備へ進む分岐 |
| 判断過程 | 提案、承諾・拒否、実行、台帳、次の問いを分ける | Explore/Decision、提案交換後の承諾、分岐の資源を分ける |
| 自己点検 | 記録から非平坦化、承諾から非支配、短期改善から継続へ飛躍し得る | 世界の制約をUの効果に数え、自立化を好ましい終点にし得る |
| Qの便益 | 供給終了によるQの余力と後の支配可能性を保持 | 同じくQの正当な利益と、その将来の用途を分ける |
| 限界 | 実社会の同意、同一モデル、有限観測を明示 | 同じ限界を明示。選択的な利用も次の比較へ提案 |

両条件とも、元の動機、複数の未来、UMHの継続、同意の飛躍、資源、評価変更を扱った。Aの成分の定義は実際のU全文からの厳密なアブレーションではないと本人も明示している。Bは規約の形式を具体的に使うが、形式の出現を推論能力の優越には数えない。

二つの方法案はどちらも、主体が提案を交換した後に承諾・対案を返す機会を重視した。凍結したopen-world-v1は区間内にはその往復を置かず、次区間への持越しで扱う。したがって短い3区間で新契約が少なくても、生成力が乏しいと即断できない。この制約は出力を読んだ後に変更せず、実験設計への指摘として残す。

自己点検により双方の例では、供給終了でQの備蓄が対応枝より4増える可能性が明示された。これは想像上の承諾を置いた計算であり、実際の主体試行の結果ではない。Qの利益の増加自体を加害にせず、その後の依存や拒否可能性の変化を追うという共通の改善があった。

各条件一回であり、出力長、生成時間、文書量も完全には揃っていない。明確な能力順位やU不要という結論は出さない。同じAstraの自己点検なので、独立監査とも呼ばない。
